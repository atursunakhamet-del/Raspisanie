ЗАГРУЗКА В GITHUB
1. Распакуйте архив.
2. Создайте репозиторий на GitHub.
3. Откройте Add file → Upload files.
4. Перетащите файлы и папки из архива (не сам ZIP).
5. Нажмите Commit changes.
При загрузке через браузер проверьте, что скрытые файлы .gitignore и .env.example тоже добавлены.

ВАЖНО: загрузка в GitHub сохраняет код, но не запускает сервер.
GitHub Pages размещает статические страницы. Вход, общая база, сообщения и уведомления этой версии требуют серверного хостинга. Включение Pages не запустит полноценную версию.
Работающий сайт: https://narxoz-timetable-abdulaziz.tunedcove7.chatgpt.site/planner
Свой домен можно подключить к существующему сайту без переноса в GitHub Pages.

ЛОКАЛЬНЫЙ ЗАПУСК
1. Установите Node.js 24 или новее.
2. Откройте распакованную папку в VS Code.
3. Terminal → New Terminal.
4. Выполните: node local-server.mjs
5. Откройте http://localhost:5500
6. В терминале будет First admin setup code. Используйте его для регистрации первого администратора: «Тіркелу» → «Әкімші». Придумайте свой логин и пароль (от 10 символов).
Установка npm-пакетов для этого запуска не нужна.

В комплекте исходное расписание БҚ-331 и БҚ-332, предметы, учителя и время уроков до 15:25.
Локальная база создаётся заново: действующие аккаунты, пароли, личные сообщения и изменения из базы опубликованного сайта в архив не включены.
Ученики регистрируются с корпоративной почтой @college-narxoz.kz. Подтверждения владения почтой через письмо в текущей версии нет.

Не загружайте в GitHub папку .local-data, которая появится после запуска: она содержит базу пользователей и локальные секреты. .gitignore исключает её при загрузке через Git.
Привязка к существующему проекту хостинга исключена из архива, чтобы копия не меняла работающий сайт. Для отдельного развёртывания настройте новый сервер и новую базу.
Подробности: START_RU.txt и README.md.

ПУБЛИКАЦИЯ НА VERCEL
1. Подключите этот репозиторий к проекту Vercel. В Root Directory укажите папку с vercel.json. Выберите Framework Preset → Other. Репозиторий задаёт сборщики статических файлов и Node.js API в vercel.json.
2. Создайте базу Cloudflare D1. Для новой пустой базы выполните SQL из drizzle/0000_dashing_snowbird.sql и затем drizzle/0001_worried_lockheed.sql. SQL можно применить через Wrangler: npx wrangler d1 execute <имя-базы> --remote --file <путь-к-sql>. Примените каждый файл один раз.
3. В Vercel → Settings → Environment Variables задайте D1_ACCOUNT_ID (ID аккаунта Cloudflare), D1_DATABASE_ID (ID базы), D1_API_TOKEN (токен Cloudflare с правом D1 Edit для этого аккаунта), AUTH_SECRET (случайная строка от 32 символов) и SETUP_CODE (отдельный случайный код регистрации первого администратора). Добавьте переменные для нужного окружения Vercel и храните секреты только в его настройках.
4. Выполните Deploy или Redeploy. Откройте главную страницу. Запрос к /api/config должен вернуть JSON со списком групп и setupRequired: true для новой базы. Затем зарегистрируйте первого администратора с SETUP_CODE.

В новой базе исходное расписание БҚ-331 и БҚ-332 загрузится автоматически. Чтобы перенести существующие аккаунты, сообщения и изменения расписания, отдельно перенесите базу и сохраните исходный AUTH_SECRET, от которого зависят пароли.
